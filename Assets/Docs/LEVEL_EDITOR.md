# Level Editor

Unity 编辑器内的关卡制作指南。目标是用同一套地面、角色与机关配置反复搭关，而不是为每个谜题写一次性场景脚本。

[返回 README](README.md) · [玩家规则](GAMEPLAY.md) · [工具实现](Features/TOOLS.md)

## 设计思路

- **场景负责制作，独立状态负责运行**：编辑器修改场景和配置，保存或进入 Play 前烘焙地形；运行时不直接用场景物体位置充当棋盘状态。
- **地面与占位分开**：石块、灌木、角色和机关独立放在地面上。替换地面不重建这些实体，也不改变其 ID 和关联。
- **配置优先**：通过角色类型、门条件、关联压力板、朝向和入口场景引用组合谜题，不为每关复制一套规则。
- **修改可撤销、检查不代改**：一笔绘制或一次矩形提交对应一次编辑器撤销；错误检查与修复分开执行。

## 1. 创建关卡

1. 退出 Play，打开 `TD推箱子 > 创建关卡`。
2. 从上到下填写关卡名称、资源目录、宽、高。名称使用简短英文或拼音；宽、高各为 1～64 格，下方显示地块总数。
3. 在“环境”中选择背景环境 Forest / Castle、布景种子与地面颜色。默认种子为 447。
4. 点击“创建关卡”，保存到 `Assets/TD_PushBox/Scenes/Levels` 或其子目录。已有同名场景不会覆盖，取消保存不会创建关卡；原场景有修改时会先询问是否保存。
5. 工具生成棋盘、分组、光照、固定透视镜头和外围布景，并打开“关卡编辑”。

默认不放角色、不放目标点、不铺棋盘花草，覆盖率为 0%。新建后先放角色和目标点再试玩；草稿可以先保存。

创建入口与关卡编辑是两个独立窗口。开始和选关场景在 `Scenes` 根目录，只有玩法关卡放进 `Scenes/Levels`。

## 2. 认识关卡结构

默认格距 1.12、可见地块宽 1.08、层高 0.45，坐标从 `(0,0)` 到 `(宽-1,高-1)`。运行镜头为正面俯角 60 度的透视，默认视野 50 度；Scene 视图仍可正常观察制作。

关卡根节点维护六个容器引用，工具不依赖根分组的显示名称。典型层级如下：

```text
Level
  Tiles
  Units
  Objs
    Obstacles
    Goals
    Doors
    Plates
    Movables
  Env
  Details
  RT
```

Objs 的五类分别为障碍物、目标点、门、压力板和移动物（木箱、水晶）。新放置物体自动归类；已有直属物体及这些工具分组内的物体会按类型整理，不接管作者自建的其他子分组。

角色和机关不能挂到地块下。花草与底座可以属于地块；地块替换时这些地表花草会随被替换的地块清理。

## 3. 基础编辑

打开 `TD推箱子 > 关卡编辑`，指定当前场景的关卡根节点。默认使用统一的 `Data/Authoring/PushBoxPalette.asset`。

选择分类，再点资源或工具即进入绿色“编辑中”。点“已暂停/编辑中”按钮或在 Scene 按 Esc 可暂停；暂停后不拦截 Unity 正常选择。Alt 保留 Scene 视角操作，切场景或进入 Play 会暂停编辑。

| 工具 | 使用方法 |
| --- | --- |
| 选择 | 点击当前分类的对象，在“当前对象”中检查或修改 |
| 绘制 | 点击或拖动，放置当前资源；同一笔内同一格只处理一次 |
| 矩形 | 在支持的分类拖出区域，松开提交；适用于地形及场地方案目标点 |
| 吸取 | 读取已有对象对应的资源；地块同时读取高度 |
| 移动 | 先选择对象，再点击目标格，或在“当前对象”填写格点后点击移动 |
| 擦除 | 删除当前分类命中的对象；有机关引用的压力板需要先解除关联 |

工具图标有悬停名称提示。上方可切换网格显示、聚焦棋盘或保存场景。编辑模式 Ctrl+Z 撤销制作操作；Play 中 Ctrl+Z 只撤销玩法，不会撤销场景中的制作操作。

## 4. 地面与障碍

“地形”分两组，每组三列：

| 分组 | 资源 |
| --- | --- |
| 地面 | 深棕、浅棕、浅灰、深绿、浅绿、深渊 |
| 障碍 | 高地、石块、灌木，固定同一行 |

平地五色规则相同。深渊没有支撑，不是黑色实体地板。高地、石块和灌木均为叠在原地块上的独立阻挡物，不删除底层地面。

- 基础地面默认高度层 0；高地障碍固定高出支撑地面 0.75。移除高地时擦除障碍即可露出原地面，替换地面颜色不会删除高地。
- “平地换色保留高度”只影响平地之间换色；不开启时按画笔高度绘制。
- 放石块或灌木不消除原地面，保留原颜色和高度；改变其下方地面高度时障碍随地表升降。擦除障碍不删除地面。
- 单格与矩形绘制都不删除角色或机关，不改它们的横向格点、ID 和关联，只修正落脚高度。
- 初始场地不能在有占位的格子上刷深渊、删地面或重叠放置障碍；矩形会跳过占用格，不挤走角色和机关。
- 多格物件需要同高平地。已有自定义子节点或嵌在地块 Prefab 内的实体，工具会要求先移出，避免误删。
- 坡道通过场景资源配置，画笔列表提供上述地面与障碍。不能通过单独拉伸地块模型来改变规则高度。

## 5. 配置角色、敌人与目标

在“角色”“敌方”“机关”分类选资源放置。放置生成新 ID，移动保持 ID；复制后若出现重复标识，使用关卡根节点的修复入口。

- 至少放置一名我方角色。角色能力与敌人行为见 [GAMEPLAY](GAMEPLAY.md)。
- 在机关分类放置绿色目标点。所有目标点都需要由我方同时占据，数量不能超过可用角色数，布局仍需实际求解。
- 敌人和火龙可以造成开局死亡；校验不会替作者改站位或保证谜题有解。
- 朝向影响角色辨识和火龙喷火方向。支持朝向配置的资源可用“模型朝向”选择，或在 Scene 编辑中用 Q / E 转向；Play 中 Q 是切人。
- 祭坛目前是单格阻挡模型，不会召唤。大体型妖怪仍只占一格，没有专属 Boss 阶段。

## 6. 普通门与压力板

1. 放置一个普通门和所需压力板。
2. 选中门，在当前对象或 Inspector 中将开门条件设为“压力板”。
3. 展开“关联压力板”，用 + 添加关联项，再从下拉框选择。列表只显示当前关卡中启用的压力板，并显示名称与格点。
4. 需要持续全压下才开门时关闭“再次压下切换开关”；需要每次重新全压下切换状态时开启它。
5. 保存后试玩完整的踩板、离板与重新踩板过程。

关联列表为空时不会由压力板产生开关信号；门保留其请求的初始状态。缺失或跨关卡引用会被检查拒绝，不应把箱子、门等物体塞进关联列表。

压力板上方在 Scene 常驻显示 `(X, Y)` 坐标，不需要选中。看不到时检查 Scene 的 Gizmos 开关；Game 视图不显示标签。

门关闭可以压碎木箱、压死人物；水晶不可破坏，会继续阻挡关门。压碎、死亡与压板释放可形成连锁，需要把整个机关过程纳入解法。

封印石门使用“清空敌方”规则，无需压力板；存活敌人包含火龙。不要把普通门的压力板开关逻辑和封印门混为一套条件。

## 7. 外围布景与花草

“环境”栏的顺序为背景环境、布景种子、刷新布景、花草覆盖率、刷新花草及清空按钮。花草通过覆盖率、刷新和清空管理。

- **刷新布景**：按主题、尺寸和种子重建工具登记的外围分组，不修改棋盘、角色、机关、镜头和棋盘花草。
- **刷新花草**：按覆盖率随机替换棋盘上的花草，不改变外围布景。0% 不铺设；刷新会替换已铺设花草，不叠加。
- **清空花草**：清除棋盘花草，不删树木、障碍或外围布景。
- 花草没有碰撞或玩法组件，可贴合地面、高地及石块顶面；不能铺到深渊或角色/普通机关占用的格子。
- 手工环境替换前需要确认；待替换分组含玩法或自定义脚本时拒绝删除。独立手工布景默认保留。
- 刷新布景和花草分别支持整次撤销，不会自动重刷作者已经绘制的地面颜色。

## Scene 攻击范围

Scene 开启 Gizmos 时会常态显示敌人攻击格：守卫四向 1 格、哨兵四向 2 格，火龙仅朝向前方。红色为普通攻击，橙色为火焰；范围与实战共用计算，遇障碍或关门立即截断，不包含阻挡格。编辑时读取当前摆放和机关配置，Play 时读取当前棋局；移动障碍、开关门或撤销后更新。显示只存在于 Scene，不进入 Game 视图。

## 8. 配置选关入口

1. 打开 LevelSelect，在“机关”放置“关卡入口”。
2. 在当前对象中填写编号，最多 3 字符，例如 `1-1`。
3. 从“对应关卡”下拉框选择 `Scenes/Levels` 内的场景。引用使用 GUID，目录内重命名或移动仍可定位；删除或移出目录会失效。
4. 保存目标关卡，等待编辑器生成地图预览与入口目录；再保存选关场景中的入口配置。
5. 进入 Play，走到入口，分别测试 E 进入和按住 V 预览。

通关后的下一关顺序取自庭院中已配置、启用且可加载的 `x-y` 入口。编号应唯一，按数字大小排序；未配置与重复编号不参与路线。只在 Levels 文件夹新增场景、但不配置入口，不会自动加入下一关路线。

入口不挡路、不搬运，也不是通关目标点。保存后自动更新离线预览和入口目录，不改变构建列表，也不会自动在庭院中替作者摆放入口。“自制关卡”列表尚不连接实际关卡加载。

发布名单在 Unity 的 `File > Build Settings > Scenes In Build` 单独管理：添加并勾选开始场景、选关场景以及入口实际关联的关卡，开始场景放在首位。草稿关卡可以不加入名单；如果它已有启用的入口，需要先取消对应入口的关联或停用入口。自动预览不会重新勾选已禁用的场景，也不会改变排序。

构建前与“检查工程”会只读检查启用场景及其菜单/入口跳转：目标必须存在并启用，入口目录必须与目标一致。未配置目标的入口可作为占位保留。缺失预览不会阻止进入关卡，构建检查也不拍摄预览、不保存或修复场景；出现目录过期提示时先保存目标关卡，等待自动更新后重试。

## 9. 场地变化方案

顶部切换“初始场地 / 场地变化”，选择已有方案或新建方案。新建时复制当前地形与目标点作为基础，初始角色和机关继续被引用，不重复生成。

可编辑地形、障碍、敌人、机关、目标点，以及 Boss 预制体和出生位置。普通门可配置变化后的压力板引用。完成后点击“校验方案”，再保存。

预览只临时隐藏原显示并生成模型，不销毁初始实体；保存、退出模式、进入 Play 或关闭窗口后会清理。**运行中的触发、祭坛召唤、坍塌与撤离流程尚未接入**。详细数据边界见 [TERRAIN_CHANGES](Features/TERRAIN_CHANGES.md)。

## 10. 检查、同步与试玩

选中关卡根节点，在 Inspector 使用：

| 操作 | 用途 |
| --- | --- |
| 检查当前关卡 | 只读检查地面、占位、ID、位置、组件和引用，错误可定位对象 |
| 按格点对齐场景 | 以已有格点为准恢复场景位置，不改 ID |
| 按场景位置更新格点 | 以直接拖动后的场景位置为准，校验后更新格点并吸附，整次可撤销 |
| 修复缺失或重复标识 | 只修复异常 ID，保持对象引用，支持撤销 |

直接使用 Unity 移动工具不会自动更新玩法格点，要明确选择一种同步方向。关卡编辑器的移动工具会同时更新二者。

保存会烘焙地形；进入 Play 前统一检查已加载关卡，有错误则取消进入，不自动修复布局。草稿仍可保存。进入 Play 后先点击 Game 视图，再按 [GAMEPLAY](GAMEPLAY.md) 测试。

`TD推箱子 > 检查工程` 读取已打开场景的当前内容，并临时加载未打开场景检查；不保存作者场景、不修改方案或构建配置，只关闭自己临时打开的场景。校验不验证解法、死局和完整通关路径。

## 常见问题

| 现象 | 优先检查 |
| --- | --- |
| Scene 点击无效果 | 指定了正确关卡、处于“编辑中”、资源分类匹配、鼠标在 Scene 而不是 Game |
| 要露出高地下方地面 | 在地形栏选择并擦除高地障碍；底层地面保留，可再单独换色 |
| 灌木或石块放不上 | 下方有可通行地面，格子没有其他实体占位；障碍不允许重叠 |
| 压力板下拉没有候选 | 压力板属于当前关卡、处于启用状态；不是外围模型或其他场景的对象 |
| 入口预览没有更新 | 先保存目标关卡并等待导入；未保存修改不会被强制保存去拍图 |
| Play 被取消 | 查看 Console 或“检查当前关卡”，修复坐标、ID、支撑与引用 |
| 自动整理后场景有修改标记 | 核对分组与命名后手动保存；工具不会强存你当前的场景 |
